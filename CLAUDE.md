Цей файл — точка входу для будь-якого чату/сесії Claude, яка працює над цим проєктом.
Прочитай його першим, перед тим як щось редагувати.

## Що це за проєкт

**XPRNT STIKER IMPOSER** — локальний веб-застосунок для розкладки (імпозиції) прямокутних
наліпок на аркуш друку. Завантажується PDF-артворк → застосунок рахує сітку наліпок на
аркуші (SRA3/SRA3+ або кастомний розмір) → генерує:

- друк-готовий PDF (тайлінг артворку по сітці + мітки приводки),
- шаблон PDF з мітками (для повторного використання),
- файл різу `.plt` (HPGL) для плотера,
- опційно — векторний PDF контуру різу (для сторонніх програм розкрою).

Є batch-режим: кілька артворків за раз, з дедуплікацією однакових шаблонів сітки.
Все пакується в один zip.

Проєкт належить PaperFox і використовується у виробничому процесі (друк + плотерний різ).

## Стек

- **Backend:** Python 3.10+, FastAPI + Uvicorn
- **PDF:** `pypdf` (читання/компонування сторінок), `reportlab` (генерація шаблону й
  контуру різу), `PyMuPDF`/`fitz` (растрові мініатюри для прев'ю)
- **Frontend:** чистий HTML/CSS/vanilla JS, без фреймворків, `web/`
- **Запуск:** локально, `run_server.py` піднімає uvicorn і сам відкриває
  `http://127.0.0.1:8000` у браузері; `run.bat` — те саме одним кліком на Windows

## Структура коду

```
run_server.py, run.bat        — локальний лаунчер (сервер + автовідкриття браузера)
server/app.py                 — FastAPI app, монтування web/ як статики, підключення роутерів
server/models.py              — Pydantic-моделі запитів/відповідей
server/session_store.py       — тимчасове сховище завантажених PDF (in-memory + temp dir, TTL 2 год)
server/core/layout.py         — математика розкладки: auto-fit сітки, ручний override cols/rows/orientation
server/core/pdf_inspect.py    — визначення розміру артворку з PDF (TrimBox/MediaBox)
server/core/marks.py          — спільні мітки приводки (registration marks) для шаблону й контуру
server/core/pdf_template.py   — генерація шаблону PDF (мітки + підпис + невидима сітка комірок)
server/core/cut_contour_pdf.py— векторний PDF контуру різу (магента-лінії для сторонніх програм)
server/core/plt_writer.py     — генерація HPGL/.plt (дві стратегії: суцільні лінії сітки при gap=0,
                                 окремі прямокутники-комірки при gap>0)
server/core/print_pdf.py      — фінальний друк-PDF: тайлінг артворку по сітці, авто-поворот
                                 під орієнтацію комірки, contain-fit або деформація (deform)
server/core/packaging.py      — упаковка результатів у zip (одиночний і batch)
server/core/thumbnail.py      — растрове прев'ю першої сторінки PDF для UI
server/routes/                — API: /api/config, /api/analyze, /api/layout,
                                 /api/generate, /api/generate-batch, /api/session/{id}
server/utils/constants.py     — дефолтні відступи, пресети аркушів (SRA3/SRA3+), список матеріалів
server/utils/naming.py        — формування імен файлів/папок результату
web/                           — фронтенд: index.html (форма: артворк → аркуш/розмітка → замовлення),
                                 app.js (стан + виклики API + SVG-прев'ю), style.css
```

## Як запустити локально

```bash
pip install -r requirements.txt
python run_server.py
```

або подвійний клік на `run.bat` (Windows). Відкриється `http://127.0.0.1:8000`.

## Правила роботи Claude над цим проєктом

### 1. Перед початком роботи — перевір, що це остання версія коду

Проєкт розробляється з кількох комп'ютерів. Перш ніж редагувати файли:

1. Переконайся, що в папці проєкту вже є git-репозиторій (`.git`). Якщо ні — див. розділ
   "Git-синхронізація" нижче, спершу треба його ініціалізувати.
2. Якщо репозиторій є, виконай `git status`. Якщо є незакомічені зміни, з'ясуй у користувача,
   чи це очікувано, перш ніж перезаписувати файли.
3. Виконай `git fetch`, потім `git log HEAD..origin/<поточна_гілка> --oneline`. Якщо там є
   коміти — значить на GitHub є новіша версія, якої немає локально. У такому разі:
   - повідом користувача, що локальна копія відстає від GitHub;
   - запропонуй `git pull` перед тим, як вносити нові зміни (інакше ризик редагувати
     застарілий код і отримати конфлікт при наступному push).
4. Тільки після цього починай редагування.

### 2. Онови цей файл (CLAUDE.md), якщо:

- додано новий файл/модуль або суттєво змінилась структура проєкту;
- призначення чи логіка існуючого модуля змінились настільки, що опис вище став неточним;
- змінились команди запуску, залежності (`requirements.txt`) або дефолтні параметри
  (пресети аркушів, матеріали, відступи).

Дрібні правки (баг-фікс, рефакторинг без зміни інтерфейсу/поведінки) оновлення файлу
**не потребують**.

Коли оновлюєш — онови також розділ "Останній стан" нижче: 1–3 речення, що зроблено і
що лишилось, з датою. Це і є той самий "підсумок роботи", який дозволяє почати новий чат
з нуля і одразу зрозуміти, на чому зупинились.

### 3. Наприкінці сесії — закомить і запуш зміни

Якщо репозиторій уже налаштований, після завершення суттєвого шматка роботи:

```bash
git add -A
git commit -m "короткий опис змін"
git push
```

Це те, що дозволяє продовжити роботу з іншого комп'ютера — там достатньо буде `git pull`.

## Git-синхронізація

GitHub-репозиторій вже створено: https://github.com/VolodymyrVlasov/XPRNT-Sticker-Imposer.git
(поки що порожній, без жодного коміту). Локально папка **ще не є git-репозиторієм** (немає
`.git`, хоча `.gitignore` вже є). Один раз потрібно виконати в терміналі, у корені папки
проєкту:

```bash
git init
git add .
git commit -m "Initial commit"
git remote add origin https://github.com/VolodymyrVlasov/XPRNT-Sticker-Imposer.git
git branch -M main
git push -u origin main
```

> Примітка (2026-09-16): хмарна сесія Claude не змогла виконати ці кроки сама — до цього
> комп'ютера підключені лише файлові інструменти (без термінала), а прямий `git push` із
> хмарної пісочниці Claude в цей репозиторій блокується політикою безпеки пісочниці
> ("repository is not in this session's authorized repository set"). Тому команди вище
> потрібно виконати вручну, один раз, з цього комп'ютера.

Постійний робочий цикл між комп'ютерами:

- **Перед початком роботи на будь-якому комп'ютері:** `git pull` (обов'язково, навіть якщо
  здається, що нічого не змінювалось — так уникаються конфлікти).
- **Після завершення роботи:** `git add -A && git commit -m "..." && git push`.
- Якщо працюєш через Claude на різних комп'ютерах без хмарної сесії Claude Code —
  саме git (push/pull), а не сам чат, є джерелом правди щодо актуальної версії коду.
  Тому крок 1 із розділу "Правила роботи Claude" вище — не формальність, а те, що реально
  захищає від втрати змін.
