Цей файл — точка входу для будь-якого чату/сесії Claude, яка працює над цим проєктом.
Прочитай його першим, перед тим як щось редагувати.

## Що це за проєкт

**XPRNT STIKER IMPOSER** — локальний веб-застосунок для розкладки (імпозиції) прямокутних
наліпок на аркуш друку. Завантажується PDF-артворк → застосунок рахує сітку наліпок на
аркуші (SRA3/SRA3+ або кастомний розмір) → генерує:

- друк-готовий PDF (тайлінг артворку по сітці + мітки приводки),
- шаблон PDF з мітками (для повторного використання),
- файл різу `.plt` (HPGL) для плотера,
- опційно — векторний PDF контуру різу (для сторонніх програм розкрою).

Є batch-режим: кілька артворків за раз, з дедуплікацією однакових шаблонів сітки.
Все пакується в один zip.

Проєкт належить PaperFox і використовується у виробничому процесі (друк + плотерний різ).

## Стек

- **Backend:** Python 3.10+, FastAPI + Uvicorn
- **PDF:** `pypdf` (читання/компонування сторінок), `reportlab` (генерація шаблону й
  контуру різу), `PyMuPDF`/`fitz` (растрові мініатюри для прев'ю)
- **Frontend:** чистий HTML/CSS/vanilla JS, без фреймворків, `web/`
- **Запуск:** локально, `run_server.py` піднімає uvicorn і сам відкриває
  `http://127.0.0.1:8000` у браузері; `run.bat` — те саме одним кліком на Windows

## Структура коду

```
run_server.py, run.bat        — локальний лаунчер (сервер + автовідкриття браузера)
server/app.py                 — FastAPI app, монтування web/ як статики, підключення роутерів
server/models.py              — Pydantic-моделі запитів/відповідей
server/session_store.py       — тимчасове сховище завантажених PDF (in-memory + temp dir, TTL 2 год)
server/core/layout.py         — математика розкладки: auto-fit сітки, ручний override cols/rows/orientation
server/core/pdf_inspect.py    — визначення розміру артворку з PDF (TrimBox/MediaBox)
server/core/marks.py          — спільні мітки приводки (registration marks) для шаблону й контуру
server/core/pdf_template.py   — генерація шаблону PDF (мітки + підпис + невидима сітка комірок)
server/core/cut_contour_pdf.py— векторний PDF контуру різу (магента-лінії для сторонніх програм)
server/core/plt_writer.py     — генерація HPGL/.plt (дві стратегії: суцільні лінії сітки при gap=0,
                                 окремі прямокутники-комірки при gap>0)
server/core/print_pdf.py      — фінальний друк-PDF: тайлінг артворку по сітці, авто-поворот
                                 під орієнтацію комірки, contain-fit або деформація (deform)
server/core/packaging.py      — упаковка результатів у zip (одиночний і batch)
server/core/thumbnail.py      — растрове прев'ю першої сторінки PDF для UI
server/routes/                — API: /api/config, /api/analyze, /api/layout,
                                 /api/generate, /api/generate-batch, /api/session/{id}
server/utils/constants.py     — дефолтні відступи, пресети аркушів (SRA3/SRA3+), список матеріалів
server/utils/naming.py        — формування імен файлів/папок результату
web/                           — фронтенд: index.html (форма: артворк → аркуш/розмітка → замовлення),
                                 app.js (стан + виклики API + SVG-прев'ю), style.css
```

## Як запустити локально

```bash
pip install -r requirements.txt
python run_server.py
```

або подвійний клік на `run.bat` (Windows). Відкриється `http://127.0.0.1:8000`.

- **2026-09-17** — Виправлено дублювання контуру порізки у фігурних стікерах.
  Причина (знайдено на реальному файлі клієнта, підтверджено через
  `get_drawings(extended=True)`): дизайнер продублював лінію різу в Illustrator і
  замість видалення сховав стару копію через прозорість (opacity групи = 0%),
  а не видимість шару — обидві копії мають однакову геометрію, різну товщину лінії
  (1.0pt невидима і 0.283pt = 0.1мм видима). Звичайний `page.get_drawings()`
  (без extended-режиму) не бачить прозорість вкладеної transparency-групи і
  показує обидві копії як однаково видимі strokes — тому проста перевірка
  "чи є колір/товщина" нічого б не відфільтрувала. Виправлено в
  `inspect_shape_pdf` (`server/core/shape_inspect.py`) двома шарами: (1) основний
  фікс — підрахунок кумулятивної прозорості через вкладені transparency-групи
  (`get_drawings(extended=True)`), контури з нульовою сукупною прозорістю
  ігноруються; (2) додатковий запобіжник — геометричний дедуп повністю
  ідентичних (з точністю ~0.001мм) підконтурів на випадок, коли обидві копії
  видимі. Підконтури з дійсно різною геометрією (напр. форма з отвором) не
  зачіпаються. Виправлення в одному файлі (`shape_inspect.py`) автоматично
  закриває і прев'ю, і contour-PDF, і PLT, бо всі вони читають один і той самий
  список підконтурів.

  `quantity` (як і в одиночному режимі), `orientation`/`quantity` прибрано з
  рівня `BatchGenerateRequest`/`ShapeBatchGenerateRequest` (лишились спільними
  тільки аркуш/відступи/матеріал/замовлення й чекбокс контуру різу).
  `generate_batch.py`/`generate_batch_shape.py` рахують сітку й
  sheets_needed окремо для кожного файлу. ⚠️ Тимчасовий ефект: поточний
  фронтенд (`web/app.js`) ще шле старий формат запиту (спільні orientation/
  quantity) — batch-режим через UI поверне 422, доки не підключиться
  фронтенд-стадія з попапом властивостей файлу. Одиночний режим не
  зачеплений.

  **Стадія 3 (бекенд, стрілка напряму подачі) — виконано.** Додано друковану
  стрілку (суцільний чорний трикутник, вістрям вгору, по центру ширини
  аркуша, на висоті верхніх кутових міток приводки) у
  `server/core/marks.py`, `draw_registration_marks()` — автоматично
  потрапляє на всі три виходи, що використовують цю функцію: шаблон PDF і
  фінальний друк-PDF (прямокутний режим), друк-PDF (фігурний режим),
  векторний PDF контуру різу (прямокутний режим). Розмір/позиція підібрані
  орієнтовно (`FEED_ARROW_WIDTH_MM`/`FEED_ARROW_HEIGHT_MM`), звірені з
  рендером, але не з референсним фото піксель-в-піксель — можливе
  подальше тонке підлаштування за фідбеком користувача. Під час рендер-
  перевірки виявилось і виправлено: початкова вертикальна позиція
  (вістря на висоті `mark_offset - 0.5`мм) заходила у смугу вже наявного
  підпису назви шаблону (той самий, що малює `pdf_template.py`, теж по
  центру ширини аркуша) — вістря стрілки зсунуто нижче
  (`mark_offset + 2.0`мм), висоту зменшено до 7мм, тепер є чистий
  проміжок (~1.5мм) між підписом і стрілкою на всіх перевірених виводах.

  2/5:3/5, відступ сайдбару "Типи розкладки".
